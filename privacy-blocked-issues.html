Privacy Policy

Blocked Issues, Dependency & Linked Issues Gadgets for Jira — last updated 25 August 2026

The short version: this app stores nothing and logs nothing about you. It runs entirely on Atlassian's own infrastructure, reads the work items and issue links you already have access to in order to draw a table on your dashboard, and forgets them as soon as the gadget has rendered. No data is sent anywhere else, and there is no server of ours for it to be sent to.

What the app does with your data

The app is an Atlassian Forge app. Forge apps run on infrastructure operated by Atlassian, inside Atlassian's own cloud — this app qualifies for Atlassian's Runs on Atlassian programme, which means it uses no external hosting of any kind.

When a dashboard gadget is displayed, the app calls Jira's REST API on your behalf and reads:

  • work items matching the project, saved filter or JQL query you configured in the gadget,
  • for each of them: key, summary, current status, priority, assignee and parent — only the fields the table actually shows,
  • the issue links of those work items — which item is linked to which, by which link type, and in which direction. This is the subject of the app: without the links there is nothing to report,
  • the change history of those work items, restricted to entries for the Link field. Each such entry records when a link was created or removed. This is the only place in Jira where the age of a dependency exists, and it is what makes “blocked for 17 days” possible at all,
  • for the blocking work items themselves, in a second query: their assignee, status and due date, so the table can say who holds the blocker. This lookup can be switched off in the gadget settings,
  • the list of issue link types defined on your site, in order to detect which of them describe blocking on your instance — including renamed or translated ones,
  • the names of your projects and of your favourite filters, so the gadget settings can offer them.

Those values are used to compute the table and are then discarded. They are held only in memory for the duration of the request that renders the gadget.

What the app does not do

  • No storage. The app writes nothing to Forge storage, no database, no cache, no file. Only the gadget's own settings — the project or query you chose and the display options — are kept, and those are held by Jira as part of the dashboard, not by us.
  • No logging of your data. When a Jira request fails, the app records the request path and the HTTP status code and nothing else. It never writes a response body, a query or a work item to a log, because a rejected JQL query can contain a person's name.
  • No transmission to third parties. There is no external endpoint, no analytics, no telemetry, no advertising, no tracking pixels. The app makes no egress request of any kind.
  • No profiling and no automated decision-making.
  • No writing. The app never creates, edits, links, unlinks or deletes anything in your Jira.
  • No access beyond your own. The app calls Jira as the viewing user, so it can only ever read work items that user is already permitted to see. It cannot widen anyone's access, and two people looking at the same gadget may correctly see different numbers.

Permissions the app requests

read:jira-work — read work items, their links, their change history, fields and projects. This is the only scope requested, and it is read-only.

Personal data under the GDPR

The data read may contain personal data: the display name of an assignee, and the name of the person who created or removed a link, as recorded in the change history. The app processes such data only transiently to render a table, on the instruction of your organisation as the controller, and never retains it. Atlassian remains the processor for the underlying Jira data; the legal basis for that processing is your organisation's agreement with Atlassian. Because nothing is retained, there is no data of yours held by us to export, correct or erase.

Sub-processors

None. The app has no infrastructure outside Atlassian's.

Data location

Wherever your Atlassian site is hosted. The app introduces no additional location, and no data crosses a border that Atlassian's own hosting does not already cross.

Security incidents

Since no data is stored, a compromise of the app could not expose retained customer data. Should a security issue nonetheless arise, it will be reported to affected customers and to Atlassian without undue delay via the contact address above.

Changes to this policy

If the app ever begins to store data, this page will be updated before that version is released, and the change will be described in the app's release notes on the Atlassian Marketplace.
