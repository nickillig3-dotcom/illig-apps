Story Points Sum & Epic Progress

Documentation for the Jira Cloud dashboard gadgets by Illig Apps

Install

A Jira administrator installs the app from the Atlassian Marketplace. There is nothing to configure afterwards and no account to create: the app runs on Atlassian’s own infrastructure and reads your issues through Jira’s API as the person looking at the gadget.

Add a gadget to a dashboard

  1. Open Dashboards and pick the dashboard you want, or create one.
  2. Choose Add gadget, search for Story points, and add Story Points Sum or Epic Progress.
  3. The gadget opens its settings straight away. Fill them in and choose Save.

To change the settings later, use the gadget’s … menu and choose Edit, or switch the whole dashboard to edit mode.

Settings

Saved filter
Pick one of your favourite filters. Choosing a filter overrides the JQL box below it.
JQL
Any JQL query, for example project = ABC AND sprint in openSprints(). Used when no saved filter is chosen.
What to add up
Story point estimate, original estimate, time spent, or any other numeric field on your site. Choose Number of issues to count instead of adding up. The list is read from your own instance, so it contains your custom fields under the names your site uses.
Group by
Status, status category, assignee, reporter, priority, issue type, project, resolution, parent (epic), label, component, fix version or sprint. Epic Progress always groups by parent and does not offer this setting.
Order
Largest total first, Most issues first, Furthest along first or Alphabetical.
Rows shown
How many rows to display, up to 100. Rows beyond the limit are counted in the total and reported underneath the table.
Issues read at most
An upper bound on how many issues the gadget reads for one refresh, up to 10,000. Lower it on very large queries if the gadget feels slow.
Show rows whose total is zero
Keeps groups that add up to nothing, so an empty status or an unstarted epic still appears.
Refresh
Never, or every 5, 15 or 60 minutes.

Reading the numbers

The line at the top is the grand total: how much of the chosen field the query adds up to, and how many issues that came from. The lozenge beside it is the share of that total sitting in a status whose category is Done. Each row below is one group, with its own total and issue count. Epic Progress shows completed against total for each epic instead.

What the gadget tells you when it cannot be sure

  • More issues than were read. If the query is larger than the Issues read at most limit, the gadget says how many issues it counted and roughly how many exist, instead of presenting an incomplete total as if it were final.
  • Groupings that overlap. Labels, components, sprints and fix versions can hold several values on one issue, so an issue can appear in more than one row. The gadget says so, rather than quietly showing rows that add up to more than the total.
  • Rows not shown. If the row limit hides groups, it says how many.

Permissions and data

Every read runs as the person viewing the gadget, so two people looking at the same gadget see only the issues each of them is allowed to see. The app never writes to your issues. It runs entirely inside Atlassian, sends nothing to any external server, and stores no issue data.

Licensing

The app is free for sites with up to 10 users. Larger sites can start a free trial from the Marketplace listing; when no licence is active, the gadgets say so instead of showing numbers.

Troubleshooting

The field I want is not in the list

Only numeric fields are offered, because anything else cannot be added up. Team-managed and company-managed projects keep story points in different custom fields; both are listed when they exist on your site.

The gadget says Jira rejected the JQL

Open the query in the issue navigator to see Jira’s own error message, then paste the corrected query back into the gadget settings.

The totals look too small

Check the note underneath the table. Either the row limit is hiding groups, or the query is larger than the read limit.
