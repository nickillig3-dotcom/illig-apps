Blocked Issues, Dependency & Linked Issues

Documentation for the Jira Cloud dashboard gadgets by Illig Apps

Install

A Jira administrator installs the app from the Atlassian Marketplace. There is nothing to configure afterwards and no account to create: the app runs on Atlassian’s own infrastructure and reads your work items through Jira’s API as the person looking at the gadget.

Add a gadget to a dashboard

  1. Open Dashboards and pick the dashboard you want, or create one.
  2. Choose Add gadget, search for Blocked or Dependencies, and add Blocked Issues or Dependencies.
  3. The gadget opens its settings straight away. Fill them in and choose Save.

To change the settings later, use the gadget’s … menu and choose Edit, or switch the whole dashboard to edit mode.

Save and Cancel sit at the top of the settings form, not at the bottom. A gadget’s settings frame is only as tall as the dashboard column it lives in, and this form is longer than that — with the buttons underneath, a narrow column clips them and the settings cannot be saved at all. They are at the top on purpose.

What the two gadgets show

Blocked Issues

Every work item in your selection that is waiting on an unfinished blocker, one row each:

Blocked work itemKey, summary, current status and parent.
Waiting onEvery blocker of that item: key, summary, status and — if the lookup is switched on — who it is assigned to.
Blocked forHow many days the oldest still-open blocking link has existed. today for a link created today, unknown when the change history does not say. Amber from 14 days, red from 30.
AssigneeWho holds the blocked item, or Unassigned.

Above the table: how many items are blocked, how many blocking links there are, and how many have been stuck for two weeks or more. Optionally a breakdown by assignee, project, parent, priority or status, each with the longest wait in that group.

Dependencies

The same links, aggregated into a matrix: which project or parent blocks which.

BlocksThe side that others are waiting on.
Waiting on itThe side that is waiting. Marked outside when it lies beyond your selection.
LinksHow many links make up the pair, and how many of those are still open.
For exampleA few of the actual work item keys behind the number.

Cross-project dependencies stop being something you find out about in a stand-up.

Which link types mean “waiting for”
The list is read from your own site, so it shows the link types you actually have, with the wording you actually use. Leave everything unticked and the app uses every type whose inward description describes blocking — that covers renamed and translated types. Tick specific ones to override the detection.
Break down by (Blocked Issues only)
No breakdown, assignee, project, parent, priority or status.
Show dependencies (Dependencies only)
Between projects, or between parents (epics).
Only work items that are not done
On by default. A finished item is not waiting for anything, however many links it still carries.
A finished blocker no longer blocks (Blocked Issues only)
On by default. Links to a blocker that is already done are left out, and the gadget says how many it left out. Switch it off to see them.

On by default. Costs one extra Jira call for the whole table — not one per row. Switch it off if you do not need the column.
Rows shown
10, 15, 25, 50 or 100. The rows kept are the ones that have been waiting longest; the gadget says when it is showing fewer rows than it found.
Work items read at most
An upper bound on how many work items the gadget reads, between 100 and 5000, 2000 by default. If the bound is reached the gadget says so instead of showing a smaller number as if it were complete.

Where “blocked for N days” comes from

Jira knows which items are linked. It does not offer the age of a link anywhere in its own reporting. The app reconstructs it from the change history:

  1. Creating or removing a link writes a change history entry on both work items, with the other item’s key in the entry. The blocked item therefore carries the record of its own blocker — no second lookup is needed to date it.
  2. The most recent creation entry for that blocker is the moment the dependency began; today minus that date is the number shown.
  3. The direction never comes from the entry’s text. That text is written in English even on a German or French site, so parsing it would break outside English. The direction comes from the link itself, the timestamp from the entry, the identity from the key it names.

The two gadgets together take two Jira calls for a whole dashboard: one search that returns the work items, their links and their change history at once, and one more that fetches the blockers’ assignees. Not one call per row.

The cases where the gadget says it is not sure

“Only the first N work items of this selection were read”
The selection is larger than the limit, so items further down are missing. Narrow the filter or raise the limit.
“N links have no creation entry in the change history”
Their age is shown as unknown rather than guessed. This happens when the history was trimmed, or when the item was imported with its links already in place.
“The blockers’ assignees could not be read”
The second call failed, so that column is left empty rather than filled with something wrong. Every other figure is still correct.
“N links are to a finished blocker and are not counted”
Exactly what the toggle above does, stated so the total is not read as complete.
“N links point at a work item outside the selection”
Its parent cannot be read from the link, so those rows are grouped by project instead of by parent.
“No link type on this site describes blocking”
Nothing can be detected automatically. Tick the types that mean “waiting for” in the settings.

Limits worth knowing before you buy

  • The age of a link is the age of the link, not of the wait. An item linked long after the work stalled shows the shorter figure — the honest one.
  • A link whose other end you cannot see is not shown to you. The gadget reads as the viewer, so two people may correctly see different tables.
  • Sub-tasks are included unless your query excludes them.
  • The app reports on links only. An item that is stuck for a reason nobody wrote down as a link cannot appear.

Permissions and data

The app asks for a single scope, read:jira-work, and never writes to your work items. Every request runs as the person looking at the gadget, so a viewer sees only what their own Jira permissions allow. The app stores nothing, logs nothing about you — a failed request records its path and status code and no response content — runs entirely on Atlassian infrastructure and makes no request to any server outside Atlassian.
